# Kenshi RU — Переводчик модов

![kenshi-mod-translate](docs/kenshi-mod-translate.svg)

Моды Steam Workshop, ручные моды (`kenshi\mods\<мод>`) и встроенные моды игры
(`kenshi\data\rebirth.mod`, `Dialogue.mod`, `Newwworld.mod`) → на русский.
Переводит локальный ИИ (любой OpenAI-совместимый сервер), ты можешь
поправить каждую фразу в `<имя-мода>.translate.csv` (открывается в Excel)
и пересобрать `.mod` одной командой.

**Перевод пишется НА МЕСТЕ** — в папке мода в Steam Workshop или в
`kenshi\data\`, в `mods\` ничего не копируется.
Резервная копия оригинала — рядом: `<имя>.mod.orig_<хэш>.backup`.

---

## 🚀 Старт: 3 шага (~5 минут)

**Шаг 1. Установка (один раз).** Двойной клик по:

```
install.bat
```

Поставит Python-зависимости, проверит .NET 9 (и сам скачает, если нет —
без админ-прав, в папку проекта), найдёт Kenshi и Workshop-моды в Steam
и сам впишет пути в `config.json`.
Финал окна: `[ OK ]` по всем пунктам + «Установлено».

> Если Python не установлен: python.org → Windows installer → галка
> **«Add Python to PATH»** → Install, затем повторить `install.bat`.

**Шаг 2. Кто переводит (один раз).** В `config.json` — блок `llm`:
любой OpenAI-совместимый сервер (локальный или облачный):

```json
"llm": {
  "base_url": "http://localhost:11234/v1",
  "model":    "qwen3.8:27b",
  "api_key":  null
}
```

Сервер должен быть запущен: проверь `curl http://localhost:11234/v1/models`.

**Шаг 3. Переводим.** Двойной клик по:

```
./translate_mods.bat
```

Откроется **меню выбора**:

```
[1] Перевести ВСЁ — Steam Workshop + папка mods\ кенши
[2] Только Steam Workshop
[3] Только вложенные моды кенши (kenshi\mods\<мод>)
[0] Выход
```

Вводишь `1`, `2` или `3`. Два прогресс-бара (ALL/NOW), счёт — в токенах.
`Ctrl+C` не теряет прогресс — следующий запуск продолжит с того же места.

**Всё — моды переведены.** Ниже — ежедневные операции.

## 🗣 Повседневное использование

| Что хочешь сделать | Что запускаешь (двойной клик) |
|---|---|
| Перевести «все» (меню: 1) всё, 2) steam, 3) mods | `./translate_mods.bat` (явно: `--all` / `--steam` / `--mods`) |
| Перевести всё сразу: Steam Workshop + `kenshi\mods\` | `./translate_mods.bat --all` |
| Только один мод | `./translate_mods.bat "имя мода"` — ищет по имени во ВСЕХ местах: Workshop, `kenshi\data\*.mod`, `kenshi\mods\` (примеры: `"rebirth"`, `"Dialogue"`, `"Newwworld"`) |
| Пере-перевести заново (игнорируя кэш) | `./translate_mods.bat --force "имя мода"` |
| Пере-перевести ТОЛЬКО некоторые строки (не весь мод) | `./translate_mods.bat "имя мода" --lines 5` (номер строки в CSV) — или `./translate_mods.bat "имя мода" --text "фраза"` (по содержимому, без номера) |
| Только создать CSV для ручного перевода (без ИИ) | `./translate_mods.bat --no-llm "имя мода"` |
| Посмотреть/поправить перевод | файл `<имя-мода>.translate.csv` в папке мода (Excel) → сохранить → `./assemble_mod.bat "имя мода"` |
| Пересобрать все `.mod` из кэша (без ИИ) | `./rebuild.bat` |
| Проверить качество / починить | `./verify_translations.bat`, `./fix_translations.bat "имя мода"` |
| Убрать мод из кэша | `./verify_translations.bat --purge "имя мода"` |
| Найти, где лежит фраза (моды + файлы игры: `kenshi\data\*.mod`, `kenshi\mods\<мод>`, `.po`) — **с переводом строки (EN → RU), если мод уже переведён** | `./search_mods.bat "фраза"` → по умолчанию скрыты уже переведённые; `--all` — всё; вводишь номера → перевод запускается |
| Откатить перевод: вернуть EN-оригинал из бэкапа | `./revert_mods.bat "имя мода"` |
| Откатить + вычистить кэш и CSV мода | `./revert_mods.bat --clean "имя мода"` |
| Откатить все моды (спросит y/N) | `./revert_mods.bat` |
| По списку модов из файла | `./revert_mods.bat --list-file my_mods.txt` |
| Показать, что можно откатить (+ осиротевшие) | `./revert_mods.bat --list` |
| Откатить любой `.mod` (kenshi\data\, kenshi\mods\…) | `./revert_mods.bat --file "E:\SteamLibrary\steamapps\common\Kenshi\data\rebirth.mod"` |
| Убрать папки удалённых модов (обратимо) | `./revert_mods.bat --clean-orphans` |
| Полная чистка: кэш + CSV | `./clean_caches.bat` → `./clean_caches.bat --yes` |

### `<имя-мода>.translate.csv` — Excel-таблица мода

Названа как `.mod`: `Pocket Change 2.0.mod` → `Pocket Change 2.0.translate.csv`.
Разделитель `|`, столбец 1 = оригинал («якорь», **не трогать**),
столбец 2 = перевод (пусто = строка остаётся как была).

**Полный цикл:** перевести → поправить CSV в Excel → `./assemble_mod.bat "имя"` → игра.
**Откат:** `./revert_mods.bat "имя мода"` (вернёт EN-оригинал из бэкапа).

### Шпаргалка (все команды)

```
# перевод
./translate_mods.bat "имя" | --force | --no-llm | --list-file f.txt | --include-excluded
./translate_mods.bat --file "<путь>\к .mod" --label "имя"     # любой .mod-файл
# csv
./export_mod_csv.bat "имя"          # выгрузить CSV
./assemble_mod.bat "имя"            # пересобрать .mod из CSV
./rebuild.bat | <Steam-ID> | <имя>  # пересобрать ВСЕ из кэша (без LLM)
# проверка / починка
./verify_translations.bat [--details] [--fix] [--purge]
# поиск фразы по модам и файлам игры
./search_mods.bat "фраза"                       # поиск + выбор номеров + перевод
./search_mods.bat "фраза" --no-translate | --yes | --force | --ru
# откат
./revert_mods.bat "имя" | --dry-run | --list | --list-file f.txt | (все, y/N)
./revert_mods.bat --clean "имя"                 # откат + чистка кэша и CSV
./revert_mods.bat --file "<путь>\к .mod"        # любой .mod по пути
./revert_mods.bat --clean-orphans [--dry-run]   # папки удалённых модов
# чистка
./clean_caches.bat [--yes] [--state-only] [--csv-only]
python sanitize_caches.py [--list]              # «мёртвые» строки в старых кэшах
# имена/ID доступных модов
py .\csv_mod.py --list
```

## ⚙️ Настройки — `config.json`

| Поле | Что |
|---|---|
| `llm.base_url` / `llm.model` / `llm.api_key` | сервер и модель ИИ (шаг 2). Локальному серверу `api_key: null` |
| `paths.game` | папка Kenshi (обычно вписал `install.bat`) |
| `paths.workshop` | папка Workshop-модов `content\233860` (аналогично) |
| `paths.dotnet`, `paths.modtranslate_cli` | .NET и `kenshi-modtranslate.dll` (по умолчанию уже стоят) |
| `paths.state` | кэш переводов (по умолчанию `state\` в папке проекта) |

Правило путей: **относительные** — от папки проекта, **абсолютные** —
каталоги на другом диске. Изменил файл → следующий запуск подхватит.

### `state\` — кэш переводов

| Файл | Что в нём |
|---|---|
| `state\<hash>_entries.json` | переведённые строки мода (RU) |
| `state\<hash>_mapping.json` | якорь → номер записи; «продолжить с места» |

`<hash>` — 12 символов, **из имени файла мода** (тот же, что в бэкапе).
Кэш можно вычистить в любой момент (`clean_caches.bat`) —
перевод начнётся заново, ничего не потеряется
(оригинал лежит в `.orig_*.backup`).

### Файлы: что где лежит

`translate_mods.py` — ядро конвейера (перевод, кэш, resume).
`csv_mod.py` — CSV: выгрузка (`export_mod_csv.bat`), импорт и сборка `.mod` (`assemble_mod.bat`).
`rebuild_mods.py` — пересобрать все `.mod` из кэша (`rebuild.bat`).
`verify_translations.py` — проверка качества; `--fix` — починка битых строк (`fix_translations.bat`).
`validate_translation.py` — единый источник правды «что перевод, а что ключ».
`revert_mods.py` — откат. `clean_caches.py` — чистка.
`sanitize_caches.py` — «мёртвые» строки в старых кэшах.
`prefilter.py` — «стоит ли отправлять строку в ИИ».
`dict.json` — словарь терминов (раздел ниже). `exclude.txt` — чёрный список модов (regex).
`prompt.txt` — инструкция LLM. `config.json` — настройки.
`_dev/check_dict_invariant.py` — проверка инварианта `words ⊆ exact`.

### Резервные копии (в папке мода, рядом с оригиналом)

```
<имя>.mod                       ← текущий (обычно RU)
<имя>.mod.orig_<хэш>.backup     ← оригинал (из Steam) — источник отката
<имя>.mod.revert_<время>        ← RU-версия (сохраняется при откате)
<имя>.mod.new                   ← временный (появляется при apply)
```

## 📖 Словарь терминов — `dict.json`

Файл **канонических переводов**: «Holy Citizen» обязан звучать как
«Святой гражданин» во **всех** модах, даже если LLM хочет «Гражданина-святого».

```json
{
  "exact": {
    "holy citizen": "Святой гражданин",
    "storage": "ХРАНЕНИЕ"
  },
  "words": {
    "holy citizen": "Святой гражданин",
    "mercenary": "наёмник"
  }
}
```

Две секции делают **разную работу**:

### `exact` — «строка целиком = термину»

Если **вся** строка мода (без учёта регистра) равна ключу — перевод **всегда
и точно** будет значением из словаря. LLM даже не спрашивают.

Когда это важно:

- **Разделы меню и категории** (игра собирает меню по точному совпадению):
  `"storage": "ХРАНЕНИЕ"`, `"power": "ЭЛЕКТРИЧЕСТВО"`, `"mining": "ГОРНОЕ ДЕЛО"`.
  Если два мода переведут STORAGE по-разному — в игре появятся два одинаковых
  раздела. Словарь этого не даёт.
- **Имена рас, фракций, предметов, NPC**: `"black dog": "Чёрный пёс"`,
  `"cannibal skav": "Трупоед"`, `"twinblades": "Два клинка"`.

### `words` — «термин внутри фразы» (страховка)

LLM-перевод строки **проверяется**: если внутри перевода остался английский
термин из `words` (LLM иногда пропускает), скрипт подставляет русское
значение — с защитой от «рыбного» вкрапления границ слова
(`fishman` не тронет `fishmen`, `big-bones` не подцепит `big bones`).

Важно: в `words` **не** должны попадать короткие обиходные слова
(`food`, `power`, `human`…) — иначе «great power» превратится в
«great ЭЛЕКТРИЧЕСТВО». Их хватает для `exact` (целостное совпадение «меню»).

**Правило:** любой ключ, который есть в `words`, **обязан** быть и в `exact`
с **тем же** значением (инвариант; `python _dev/check_dict_invariant.py`
проверяет это одной командой). `words` — это не «второй словарь», а
**маркер «безопасно вставлять внутри фразы»**.

### Как поправить, если не нравится текущий перевод

1. **Найди строку** в CSV мода — рядом с каждым модом лежит
   `<имя мода>.translate.csv` (2 колонки: `оригинал|перевод`).
   Например `E:\SteamLibrary\...\workshop\content\233860\<id>\` для
   Steam-мода или `E:\SteamLibrary\steamapps\common\kenshi\data\`
   для встроенного. Открывается в Excel / VS Code (UTF-8).
2. **Одноразовая подправка (не трогай словарь)** — поправь вторую
   колонку нужной строки в CSV и пересобери мод:
   `./assemble_mod.bat "имя мода"`.
   Самый безопасный путь: изменится одна строка, остальные не тронуты;
   при следующем `--force` LLM снова предложит свой вариант.
3. **Массовое (чтобы во ВСЕХ модах было одинаково)** — это словарь:
   - Добавь/поправь пару в секцию **`exact`** — имя / полная строка.
   - Если это **термин, который может встречаться внутри фраз** (название
     фракции, расы) — **тоже** добавь его в **`words`** с тем же значением
     (иначе «страховка в середине фразы» не сработает).
   - Пример: хочешь, чтобы всегда было «Черновёртыши» (а не «Черновертяни»):
     `"exact": { ..., "blackshifters": "Черновёртыши" }, "words": { ..., "blackshifters": "Черновёртыши" }`
   - Пересобери моды — новая строчка перекатится в `.mod`:
     `./assemble_mod.bat "имя мода"`.

**Коротко:** `exact` = **что** переводить, `words` = **где** разрешено
вставлять (внутри фразы). В `exact` **обязаны** быть **все** ключи `words`.

## ⚔️ Запуск перевода — флаги

```
./translate_mods.bat                        # МЕНЮ: [1] всё [2] steam [3] mods [0] выход
./translate_mods.bat --all                  # Steam Workshop + kenshi\mods\<мод>\  (без меню)
./translate_mods.bat --steam                # только Steam Workshop (без меню)
./translate_mods.bat --mods                 # только kenshi\mods\<мод>\  (без меню)
./translate_mods.bat "Pocket Change 2.0"    # один мод по имени
./translate_mods.bat 1173662576             # один мод по **Steam-ID** (уникальный номер мода в Workshop,
                                                                 # виден в ссылке steamcommunity.com/shared/filedetails/… )
./translate_mods.bat --file "<путь>" --label "имя"   # любой .mod-файл по пути
```

> **ВСТРОЕННЫЕ моды игры** (`kenshi\data\*.mod`: `rebirth`, `Dialogue`,
> `Newwworld`) **никогда не входят** в «перевести всё»
> (`--steam`, `--mods`, `--all`) — только по явном имени:
> `./translate_mods.bat "rebirth"`.
> Причина: это 3–10k строк каждый — их перевод осознанное действие.

### Флаги

| Флаг | Что делает |
|---|---|
| `--steam` | **«Все моды» = только Steam Workshop** (пункт `2` меню, но без него) |
| `--mods` | **«Все моды» = только `kenshi\mods\<мод>\*.mod`** (ручные, не Workshop; пункт `3` меню) |
| `--all` | **«Все моды» = Steam Workshop + `kenshi\mods\<мод>\*.mod`** (всё, что можно автоматически; пункт `1` меню) |
| `--force` | **Пере-перевести всё заново** (игнорирует кэш, бэкап не трогает) |
| `--no-llm` | **Не ходить в LLM** — извлечь строки и создать `<имя>.translate.csv` (RU-колонка пуста — для ручного перевода). Дальше: Excel → `./assemble_mod.bat "имя"` |
| `--include-excluded` | Переводить даже моды из `exclude.txt` |
| `--temperature <число>` | Переопределить `temperature` из `config.json` на этот запуск (0–2). Пример: `./translate_mods.bat --temperature 0.3 --force "имя"` — более «сухой», предсказуемый перевод |
| `--list-file файл.txt` | Список модов (одна строка = имя или ID) |
| `--file <путь> --label <имя>` | Перевести **произвольный `.mod`-файл** по пути (не только Workshop: `kenshi\data\*.mod`, `kenshi\mods\<мод>\*.mod`, т.д.; `--label` — как назвать результат в кэше) |
| `--lines "12,40-55,99"` | **Точечный перевод**: пере-перевести ТОЛЬКО строки с этими **номерами** в `<имя-мода>.translate.csv` (1 = первая строка, как в Excel; «12» — одна строка, «40-55» — диапазон, «99» — ещё одна). Все остальные строки **НЕ трогаются**. Это `--force`, но только для выбранных, не для всего мода |
| `--text "фраза"` | **Точечный перевод по тексту** (несколько `--text "А" --text "Б"` — можно): частичное совпадение (регистр не учитывается) в оригинальной строке (столбец 1 CSV). Не надо знать номер строки — ищет по содержимому |
| `--lines` + `--text` | Можно **сочетать**: LLM переведёт строки, попавшие в ЛЮБОЕ из двух списков; остальные **НЕ трогаются** |

```
./translate_mods.bat --force "Heavy Crossbow"
./translate_mods.bat --force --list-file мои_моды.txt
./translate_mods.bat --no-llm "Heavy Crossbow"     # только CSV, переведёшь сам
./translate_mods.bat "Heavy Crossbow" --lines 5    # ТОЛЬКО строка 5, остальные не трогаем
./translate_mods.bat "Heavy Crossbow" --text "Whetbone"   # по содержимому
```

### Прогресс

Два прогресс-бара в терминале (верхний `ALL` — все моды, нижний `NOW` — текущий мод),
счёт — **в токенах**. Прерывать можно `Ctrl+C` — прогресс сохранится в кэше (`state\`).
Следующий запуск того же мода **продолжит с того места**, где остановился.

### Поиск сразу показывает перевод строки

`./search_mods.bat "фраза"` ищет во всех слоях (кэш, `.mod` в Workshop,
`kenshi\data\*.mod`, `kenshi\mods\`, `.po`, описания) и печатает результаты
**таблицей** со столбцами `EN | RU | Имя мода` (рендер — `tabulate` из
`requirements.txt`, уже ставится через `install.bat`):

```
-- слой 2: .mod в Workshop — 1 совпадений --
╒══════════╤═══════════╤══════════════════╕
│ EN       │ RU        │ Мод              │
╞══════════╪═══════════╪══════════════════╡
│ No Light │ Нет света │ Amputation Table │
╘══════════╧═══════════╧══════════════════╛
```

Работает **в обе стороны**: ищешь EN-оригинал → видишь RU-перевод; ищешь
RU-текст, который уже лежит в переведённом `.mod` → видишь EN-оригинал.

**По умолчанию скрыты** строки, у которых **уже есть** перевод (RU-колонка
заполнена) — таблица показывает только то, что **ещё не переведено** (RU пустая),
что и нужно искать. Чтобы увидеть всё, включая уже переведённые, —
`./search_mods.bat "фраза" --all`. Если в слое всё уже переведено — просто
подсказка `(все N совпадений уже переведены — --all, чтобы показать)`.
Параметр `--cap N` — сколько строк печатать (default 20).

**Слой 1 (кэш `state/`) по умолчанию скрывается целиком** — там лежат *только*
уже переведённые строки (непереведённые туда не попадают), а режим по умолчанию
именно «искать непереведённое». Чтобы увидеть кэш-слой — `--all`.

**Список «Переводимые файлы»** (для запуска перевода) согласован с таблицей: по умолчанию в него попадают *только* файлы, где есть ещё
непереведённые строки (RU пустая). Файлы, где всё уже переведено,
исключаются — в конце пометка `(исключено N файл(ов), где всё уже переведено — --all, чтобы включить)`.
С `--all` — все найденные файлы попадают в список, как раньше.

## 🛡 Защита от «системных значений»

В модах есть строки-ключи (имена анимаций, техник боя, SFX-событий,
категорий построек): другие записи и бинарные ассеты `.ani`/`.sfx`
ссылаются на них по точному EN-совпадению. Перевести такую строку —
разорвать ссылку: анимация/звук/техника сломается.

**Как конвейер это ловит:**

- **Cross-reference** — строка, которая одновременно `record.Name`
  и значением какого-либо поля в том же моде, — кандидат на ключ.
  Исключается из перевода, если **похожа на идентификатор**:
  содержит `_` или `-`, либо цифры без пробелов
  (`house03-base`, `wood_dex_dummy_pole`).
- **Тип записи** — анимации (type 5, 24), события анимации (105, 112),
  техники боя (17): их `Name` всегда ключ. Исключаются.

**Важно:** `building group` / `building category` и другие **видимые в игре**
подписи (пункты меню строительства, группы построек) — **переводятся**: обе
стороны кросс-ссылок живут внутри одного `.mod` и переписываются
согласованно при apply. Настоящие ключи (внешние `.ani`/`.sfx`,
имена техник) — по-прежнему не трогаются.

Такие строки **не попадают** в `.translate.csv`, ИИ их не видит, и при apply
не записываются — остаются EN. Всё остальное (описания, диалоги,
названия предметов/персонажей/городов, **пункты меню строительства**)
переводится.

### CSV и кэш не держат «мёртвые» строки

**Единый источник правды** — `validate_translation.py`:

- `is_translatable_text(en)` — есть ли смысл переводить (ложь для
  идентификаторов, криков, уже-русского, чистых знаков и чисел);
- `finished_row(en, ru)` — строка в **CSV**: либо реальный перевод,
  либо пустая, но ПЕРЕВОДИМАЯ (остаётся в Excel для ручной доработки);
- `has_real_translation(en, ru)` — строка в **кэше** `mapping.json`:
  только реальные (`ru` не пустой и не эхо оригинала).

Гарантия:

- системные ключи (`wood_dex_dummy_pole`, `house03-base`, `bull walk`)
  **не пишутся ни в CSV, ни в кэш** — ни после LLM, ни в `--no-llm`,
  ни в `csv_mod.py export`;
- пустые переводимые строки (LLM не сдала) пишутся в CSV **пустыми** —
  их можно доработать в Excel; в кэш они не попадают
  (resume подхватит в следующей сессии и попросит LLM снова);
- настоящий перевод всегда держится (даже если `en` выглядит как ключ —
  человек/ИИ перевёл намеренно).

### Чистка старых кэшей

Кэши, созданные до фиксации, содержат переводы системных строк
под старыми индексами. `apply` их и так не применяет, но для порядка:

```
python clean_caches.py             # dry-run: что будет удалено (state\ + *.translate.csv)
python clean_caches.py --yes       # удалить; перевод начнётся с нуля

python sanitize_caches.py --list   # отчёт: сколько строк под защитой в каждом кэше
python sanitize_caches.py          # удалить их из маппингов, переиндексировать,
                                   # бэкап .pre_optionA
```

`sanitize_caches.py` не трогает `.mod`, не ходит в LLM, идемпотентен.
Откат: вернуть `<файл>.pre_optionA` на место.

## 📚 Детали для продвинутых

### 🔬 Что под капотом

- **Как переводится мод** — конвейер извлекает строки из `.mod`
  (C#-DLL `kenshi-modtranslate.dll`), батчит, шлёт в LLM; ответ
  сопоставляется со строками обратно и пересобирает `.mod` на месте.
- **Что переводится, а что нет** — текст (описания, диалоги, названия)
  да; ключи — нет: `record.Name` + тип (анимация, SFX, техника),
  строки-идентификаторы (`_`, `-`, цифры), кросс-ссылочные ключи.
  Точные правила — `validate_translation.py` и `prefilter.py`.
- **Как работает «продолжить с места»** — якорь (оригинальная строка)
  — ключ в `mapping.json`, результат — в `entries.json`. При старте
  строка ищется в кэше: реальный перевод есть — пропускаем, нет — в LLM.
- **Как CSV встраивается** — `csv_mod.py` читает кэш
  (якорь → перевод), пишет `<имя>.translate.csv` (`export_mod_csv.bat`);
  импорт — обратная сторона: читает CSV, пишет переводы в кэш.
- **Как править одну строку без полного запуска** — правь вторую
  колонку `<имя>.translate.csv` → `./assemble_mod.bat "имя"`.
  Изменение сразу попадает в `.mod`, кэш остаётся как был.

### ➕ Любая внешняя LLM (OpenAI-совместимый API)

Конвейер ходит **в одну точку**: `POST <base_url>/chat/completions`
в формате OpenAI. Поэтому подойдёт **любой сервер с OpenAI-совместимым
API** — локальный (ollama, llama.cpp /server, vLLM, LM Studio,
text-generation-webui) или облачный
(OpenAI, OpenRouter, Groq, Mistral, Together, DeepSeek и т.п.).

Меняешь в `config.json` только блок `llm`:

```json
"llm": {
  "base_url": "https://api.openai.com/v1",     // ← любой OpenAI-совместимый
  "model":    "gpt-4o-mini",                    // ← нужная модель
  "api_key":  "sk-...",                         // ← ключ (null, если локальный, без ключа)
  "http_timeout_s": 600
}
```

`api_key` опционален: `null` → заголовок `Authorization: Bearer ***
не ставится (локальные серверы часто без ключа).

**Условия совместимости** (что конвейер реально шлёт и читает):

- принимает `POST /v1/chat/completions` и отдаёт
  `choices[0].message.content` (+ `finish_reason`, `usage`);
- поддерживает `temperature` и достаточный контекст;
- лишние поля (`max_tokens`, `reasoning_effort`,
  `chat_template_kwargs.enable_thinking`) — отправляются всегда;
  часть серверов их молча игнорирует, строгие OpenAI-клоны могут
  ругаться — в таком случае закомментируй их в `config.json`.

### 🌍 Не только английский → русский

Ядро конвейера **не знает языков**: берёт строку из `.mod`, отправляет
в LLM, забирает ответ. HTTP-протокол, батчинг, ретраи, `apply`/`rebuild`
полностью независимы от пары языков. Подойдёт **любой язык-исходник**,
который понимает подключённая LLM, и целевой — любой, на который она
умеет отвечать.

По умолчанию настроено **EN → RU**: промпт, словарь и prefilter
оптимизированы под английский → русский. Для другой пары
(например, японский → русский):

1. **`prompt.txt`** — перепиши system-промпт: «переведи с *\<язык>*
   на *\<язык-цели>»* + правила (термины, имена, стиль).
2. **`prefilter.py`** — проверка «нет латиницы → нечего переводить»
   предполагает латиницу в исходнике. Для CJK/кириллицы —
   `"pre_filter": false` в `config.json` или свой regex.
3. **`validate_translation.py`** — уровень `latin` ищет латиницу
   в переводе (уровень `echo` — совпадение с оригиналом, не зависит
   от языка). Для не-латинских пар ослабь `latin` в `BAD_FIX_LEVELS`.
4. **`dict.json`** — если нужен словарь, пары
   `«исходный_текст» → «перевод»` для своей пары языков.

Всё остальное — батчинг, retry, `apply`, `rebuild`, `state\`-кэш —
работает без изменений.

### 📦 Ручная установка (если хочется «от руки»)

Проект — **Windows 10/11**, всё локально
(кроме Kenshi в Steam и LLM-сервера, если он облачный).

```
1. git clone https://github.com/KorolevOl/KenshiModTranslate.git
   (или ZIP с кнопкой «Code» → «Download ZIP» → распаковать, нап. C:\KenshiModTranslate)
2. python --version                      # 3.10+ (галка «Add Python to PATH»)
   pip install -r requirements.txt
3. dotnet --list-runtimes                # содержит Microsoft.WindowsDesktop.App 9.0.x
   (нет? dotnet.microsoft.com → .NET Desktop Runtime 9.0.x → x64)
4. config.json — вписать llm и paths (см. «Настройки»)
5. ./translate_mods.bat "имя мода"
```

### Если хочется править C#-код

Нужен **.NET 9 SDK** и соседний репо `KenshiTranslator`:

```
папка\
├─ KenshiModTranslate\        ← этот репо (csproj ссылается на ..\KenshiTranslator\KenshiCore)
└─ KenshiTranslator\
   └─ KenshiCore\KenshiCore.csproj
```

```
cd KenshiModTranslate
dotnet build -c Release
# => bin\Release\net9.0-windows\kenshi-modtranslate.dll (новый)
git add bin/Release/net9.0-windows/kenshi-modtranslate.dll && git commit
```

В обычных сценариях `dotnet build` **не нужен** — DLL уже в репозитории
и обновляется вместе с релизами.

## 🆘 «Что-то не работает»

| Симптом | Что делать |
|---|---|
| `python not found in PATH` | Поставить Python 3.10+ (галка «Add Python to PATH»), повторить `install.bat` |
| `dotnet: command not found` | `C:\Program Files\dotnet` в PATH (или `install.bat` сам найдёт) |
| `dotnet CLI failed` | .NET Desktop Runtime 9 не установлен, либо `bin\Release\net9.0-windows\kenshi-modtranslate.dll` отсутствует (должна быть в репо) |
| `You must install or update .NET` | Не установлен **.NET Desktop Runtime 9** — dotnet.microsoft.com |
| `Connection refused: localhost:11234` | LLM-сервер не запущен — поднять ollama / ollama-weldbook |
| `404 /v1/models` | `base_url` в `config.json` неверный |
| `Mod not found` (мод не в списке) | `paths.workshop` не та папка, либо мод отключён в Steam |
| Ложный-мод / пустой кэш | `./verify_translations.bat --details`, затем `--fix` |
| Неверный порядок/потеря строк | `./fix_translations.bat "имя"` — починит только битое |
| Удалить кэш мода | `./verify_translations.bat --purge "имя"` |
| Перевести заново | `./translate_mods.bat --force "имя"` (бэкап остаётся) |
| Перевод «завис» (LLM не отвечает) | Проверить `curl <base_url>/v1/models`, увеличить `http_timeout_s`, либо `--force` |
